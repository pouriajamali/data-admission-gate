# Local read-only SDK input interface

This additive facade preserves every byte of common4dab62 and frozen schema63e.
It never relabels CI/current host data, runs SDK, downloads/extracts/copies SDK,
changes limits/security or asserts product admission. Existing hosted APIs remain.
Import the identical `tools/local_sdk11_input.py` beside the62 common files.
Both `transport(rid,directory,context)` and `inspect_sdk(rid,root,context)` use
an existing read-only qualified pool; `directory/root` must be the exact SDKPath
from the pinned producer fact. The returned tree is NOT caller owned: never
write/delete/clean it. The receipt explicitly says SDK0, callerOwnsSDK=false.

Producer histories are Linux local ad63c4ad (eight successful commands) and
Windows04 experimental841b5086 (five healthy old commands plus three approved
new commands, nine total attempts). Their qualification is immutable history;
no consumer inherits producer04 caps, source, authority or product admission.
The executed byte/Git CRLF mapping is separately retained, never called identical.

Caller context retains the existing15 named keys from check_dotnet11.CTX_KEYS
and the original monotonic start/deadline. Controller/contract/profile must be
tracked inside the current checkout, main __file__ must be the controller, full
current source-pin table must exactly equal Git HEAD (excluding only itself),
and all three binding files must be byte-identical to committed blobs. Clean
source, HEAD/tree, original deadline and complete source identity are checked.
Normalize only task-owned worktree source to its committed LF bytes first;
Git's text-normalized clean status alone is insufficient for binding bytes.

The source profile keeps sdk11-own-normal-input-profile/v1 and adds an explicit
localInputRoute: rid, role, readOnlyExistingPool=true, qualifiedFactSha256. It
uses the original task caps and row ceiling. Windows additionally records an
independent authorityId and formalDotnet11Support=NOT_CONFIRMED. Scope04 uses its
two direct qualification grants. Scope06 uses the independently verified direct
human instruction01a1ea8f-e946-71b0-b4a7-40cd30723b0f in chat06 authorizing local
Windows consumption/coordination; this does NOT import04's experimental grant.
Windows06 accepts only original R06_WINDOWS1GiB/CPU1/16. Generic Linux06 is
4GiB/CPU2/64, native-linux16 alone128. Retired LinuxR3 is not revived. Other
Windows scopes are denied until their independent route is supplied.

The private admission file is a DISTINCT sdk11-local-input-current/v1 input
context (not a63e consumerAdmission). Required fields: state
OWN_CURRENT_INPUT_CONTEXT_BOUND, projectId, repository, rid, qualifiedFactPath,
qualifiedFactSha256, profileSha256, controllerSha256, ownCapsEvidenceSha256 and
sourcePinTableSha256 (SHA256 of canonical sourcePins array). It grants input
verification only. Do not alter63e enums or forge GitHub environment metadata.

Own caps use the existing sdk11-own-current-cap-evidence/v1 format. Bind current
project/repository/sourceCommit/sourceTree/profile/controller/bootstrap, worker
PID/start and actual limits, original held-before-exec identity/retained handle,
supervisor PID/start and original start/deadline. Linux uses beforeExec; Windows
heldBeforeExec. Linux requires an actual system.slice service, MainPID=current,
unchanged kill-group/SIGKILL behavior, finite kernel RuntimeMax/TimeoutStop bound
within the original deadline, actual nonroot membership and a retained live
parent pidfd. Direct cgroup clocks are not silently substituted for this guard.
Windows reuses the existing OwnJob observer/watchdog: real suspended creation,
nonbreakaway kill-on-close Job, original parent handle and exact CPU/memory/tasks.
A current CPUID check remains mandatory. Neither observation borrows producer
job settings. Missing or inconsistent proof is fail closed.

Actual SDK input checks retain complete reviewed catalogs, all physical file
hashes/namespace/modes/hardlink rules on Linux and full Windows inventory, with
no renewed clock. Source callers must retain their own native dependencies,
exact SDK graphs/locks/packages/signatures/revocation/notices/advisories, tests,
packaged literal/oracle cases, signing/publication and actual terminal proof.
No current caller is admitted by this source alone. Live validation is pending.
